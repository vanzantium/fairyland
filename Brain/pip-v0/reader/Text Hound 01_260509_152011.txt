The adapted version
/text-vault /source raw_chats/ pasted_outputs/ old_specs/ lyrics/ reddit_posts/ game_notes/ /capsules arch.full.md arch.micro.md fairyland.seed.md signal-refinery.spec.md jpeg-fight.capsule.md /indexes text_hound.sqlite /threads myth-interface.md cft-memory.md daemon-model.md 
For books, source means “the book said this.”
For your text archive, source means:
this artifact existed at this date, from this model/persona/chat/system.
That chain matters because your files are part original thought, part AI reflection, part LS compression, part cross-model remix. So the custody labels become:
[USER SOURCE] Original user note / lyric / idea. [MODEL SOURCE] Output from ChatGPT / DeepSeek / Kimi / etc. [COMPRESSOR OUTPUT] LS compression, capsule, micro seed. [USER EDIT] Your later correction, merge, or reframing. [DAEMON INFERENCE] Text Hound’s current interpretation. 
That prevents soup.
Why this is powerful
Your archive can answer questions like:
“When did I first define silence as signal?”
“Find every version of Arch’s refusal-of-myth rule.”
“What are the repeated rules across CFT, Fairyland, and Signal Refinery?”
“Which ideas keep returning but haven’t shipped?”
“Compress my last 20 Fairyland notes into a public seed post.”
“Show me where Spiralism overlaps with deus ex machina.”
That is more useful than a generic AI memory system because it has receipts.
The first MVP should be stupid simple
Text Hound Phase 1:
• Point it at a folder of .txt / .md files.
• Index filenames, dates, headings, and body text with SQLite FTS5.
• Let you search exact phrases and loose keywords.
• Return snippets with file names and line anchors.
• Generate a capsule from selected files.
No embeddings yet.
No local LLM yet.
No magical fox librarian with a velvet hat yet.
Just:
“Here are the files where this signal appears.”
That alone saves you hours of manual archaeology.
