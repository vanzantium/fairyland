2. The Architecture (Expanded)

2.1 Ingestion Pipeline

```
Kindle/KOReader/Readwise →  highlights + clippings  →  /library/highlights/book_name.md
Calibre → DRM‑free EPUB/PDF/TXT →  /library/source/book_name.epub
Audible → (if owned + lawful tool) →  /library/audio/book_name.mp3
            ↓
      Whisper transcription →  /library/transcripts/book_name.txt
Physical books → photo → OCR → note text →  /library/notes/book_name_notes.md
```

Each book gets a uniform folder containing the best version of its text: source, transcript, highlights, notes, and a capsule.md that the daemon writes when you ask it to summarize or reflect.

Wherever possible, text is the canonical format. Audio and scans are converted to text and verified against the source if you own it, but the daemon’s memory is built on text, not waveforms.

2.2 Indexing and Retrieval

Two complementary search layers:

Layer Engine Purpose
Keyword / exact SQLite with FTS5 Find quotes, character names, places; anchored search
Semantic / passage Local embedding model (all‑MiniLM‑L6‑v2, etc.) stored in a LanceDB vector index “Find the passage where magic operates like debt”

The daemon returns short source excerpts only — 2‑3 sentences — and then appends its own reasoning, always marked. This prevents a model hallucinating a book it’s never seen.

2.3 Query Layer: The Shadow Reader

When you ask a question, the daemon:

1. Runs keyword + semantic search against your entire /library/ index.
2. Retrieves the top 5‑10 chunks, ranked by relevance and recency.
3. Packs them into a prompt for a local LLM (Mistral‑7B, Llama‑3, etc.) with strict instructions:
   ```
   You are the reader’s daemon. Your only knowledge is the snippets below.
   Cite the snippet ID or page. If the information is not present, say so.
   Separate your inferences from the text.
   ```
4. The answer includes source custody labels and a signal‑score (how grounded it is in your actual library vs. prior model knowledge).

This means the AI “reads along” by using your copy of the book, not the internet’s memory.

4. Research Frontiers & Open Problems

4.1 Audible synchronization
The biggest gap. Legal audio access means: (a) Audible bookmark/clip exports, (b) using the Kindle companion book as a proxy, (c) if you own the physical CD and ripped it, Whisper transcription. A truly clean solution awaits an open audiobook standard. Until then, the daemon works best with text‑first books and treats audiobooks as a clipped shadow.

4.2 Timestamp alignment (audio + text)
If you have both an EPUB and a matching audiobook, you could align them with forced alignment tools (like montreal-forced-aligner). Then when you ask, “What was I hearing when I paused at 12:34?”, the daemon can retrieve the corresponding paragraph. This is doable but requires per‑book tuning. Worth it for deep dives, overkill for casual reading.

4.3 Privacy‑preserving design
The daemon must run entirely local — no cloud calls, no telemetry — because a reading history is a complete map of a person’s inner life. The architecture above is designed for that: local LLM, local vector store, local Whisper transcription (or local‑distil‑whisper). Even the highlights never leave your device unless you explicitly export.

4.4 Compression as curation
What makes a “good capsule”? It’s not a summary; it’s a distillation of what changed you. We can define a CAPSULE spec that includes:

· One sentence: the book’s question.
· One sentence: the most unexpected insight.
· One sentence: what to carry forward.
· List of symbols encountered.
· Coherence shift after reading (up/down).
  That creates a lightweight, lifetime‑gradient memory store.
